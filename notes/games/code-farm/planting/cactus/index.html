仙人掌

约 1540 字大约 5 分钟

2026-09-23

作物机制

  • 实体：Entities.Cactus
  • 产物：Items.Cactus
  • 仙人掌有 0 ~ 9 共 10 种尺寸，可以用 measure() 读取
  • measure(direction) 读取相邻位置，swap(direction) 交换相邻仙人掌
  • 排序要求：北侧和东侧不小于当前尺寸，南侧和西侧不大于当前尺寸

整片成熟仙人掌满足条件后，收获其中一棵会递归收获相邻仙人掌

一次连锁收获 n 棵可以得到 n ** 2 个仙人掌，因此收获的仙人掌颗数越多，收益越高，因此需要实现成片的仙人掌排序

排序目标

仙人掌种植的目标是，在收获前要把整片田排成有序状态

对于每一行的排序，最小的动作就是

if measure() > measure(East):
    swap(East)

对于每一列的排序也一样，只是把 East 换成 North

if measure() > measure(North):
    swap(North)

最终要同时满足

∀i,j,ai,j≤ai,j+1\forall i,j,\quad a_{i,j} \leq a_{i,j+1} ∀i,j,ai,j​≤ai,j+1​

∀i,j,ai,j≤ai+1,j\forall i,j,\quad a_{i,j} \leq a_{i+1,j} ∀i,j,ai,j​≤ai+1,j​

核心流程就是，将所有的地块都种上仙人掌，然后将每一行和每一列的仙人掌都排好序，得到一个完全排好序的仙人掌田，收获即可

排序流程

按行排序

给定一行的起点和宽度，每轮从左往右比较相邻格子，把较大的值推到右侧

for i in range(width - 1):
    move_to(start_x, row_y)
    for j in range(width - 1 - i):
        if measure() > measure(East):
            swap(East)
        move(East)

每完成一轮，最右边的一格就已经确定，下一轮少检查一格

这就是冒泡排序的基本思路

PS：如果某一轮没有发生交换，说明这一行已经有序，可以提前结束

changed = False

调试时建议先用 4 x 4 的小田测试一行排序，确认移动方向和交换方向都正确，再扩展到完整地图

多无人机处理

单个无人机可以排一行，使用多个无人机可以实现并行排序多行的仙人掌

主无人机可以沿着 North 移动，每到一行就启动一个排序无人机

for row in range(height):
    if row != height - 1:
        handles.append(spawn_drone(sort_by_row))
        move(North)
    else:
        sort_by_row()

启动后的无人机要保存句柄，最后统一等待，以免出现有的提前结束后先进入下个流程导致混乱和冲突

for handle in handles:
    wait_for(handle)

这一阶段只保证每一行有序，每一列还没排序，还不能收获整块田

按列排序

行排序结束后，列方向上并没有排序

所以要让每个列排序无人机沿 North 方向工作

for column in range(width):
    if column != width - 1:
        handles.append(spawn_drone(sort_by_col))
        move(East)
    else:
        sort_by_col()

最终希望每个位置都满足

ai,j≤ai+1,ja_{i,j} \leq a_{i+1,j} ai,j​≤ai+1,j​

ai,j≤ai,j+1a_{i,j} \leq a_{i,j+1} ai,j​≤ai,j+1​

也就是说，仙人掌的大小向东不减，向北也不减

排序行与列的原理

设相邻两列分别为

L=(l1,l2,…,ln),R=(r1,r2,…,rn)L=(l_1,l_2,\ldots,l_n),\qquad R=(r_1,r_2,\ldots,r_n) L=(l1​,l2​,…,ln​),R=(r1​,r2​,…,rn​)

行排序完成后，每一行都满足

li≤ri,i=1,2,…,nl_i \leq r_i,\qquad i=1,2,\ldots,n li​≤ri​,i=1,2,…,n

将两列分别按从小到大排序，记为

x1≤x2≤⋯≤xnx_1 \leq x_2 \leq \cdots \leq x_n x1​≤x2​≤⋯≤xn​

y1≤y2≤⋯≤yny_1 \leq y_2 \leq \cdots \leq y_n y1​≤y2​≤⋯≤yn​

其中 x_k 和 y_k 分别是两列的第 k 小元素

固定任意一个 k，考虑左列中不小于 x_k 的元素集合

S={i∣li≥xk}S=\{i\mid l_i\geq x_k\} S={i∣li​≥xk​}

由于 x_k 是左列第 k 小的元素，集合 S 至少包含 n-k+1 个元素

对任意 i 属于 S，都有

ri≥li≥xkr_i\geq l_i\geq x_k ri​≥li​≥xk​

所以右列中至少有 n-k+1 个元素不小于 x_k

如果 y_k < x_k，那么右列中不小于 x_k 的元素最多只有 n-k 个，与上面的结论矛盾

因此

xk≤ykx_k \leq y_k xk​≤yk​

由于 k 是任意的，所以对所有 k 都成立

xk≤yk,k=1,2,…,nx_k\leq y_k,\qquad k=1,2,\ldots,n xk​≤yk​,k=1,2,…,n

这说明分别排列两列不会破坏左右有序关系，列排序只是在此基础上补上上下方向的有序关系

因此只需要依次进行一次行排序和列排序，即可实现整片仙人掌田的排序

sort_rows()
sort_cols()

排序优化

前面讲到的排序算法是单向冒泡，每轮都从固定的一侧开始

但这种算法会重复走很多路，特别是游戏中无人机的移动也会耗费大量时间

因此可以考虑每次左右移动时都进行交换

第 1 轮  从西向东，把较大值推向东侧
第 2 轮  从东向西，把较小值推向西侧
第 3 轮  从西向东

这相当于双向冒泡，也叫做鸡尾酒排序

它不需要每一轮都走回同一个起点，减少无人机的无效移动，从而提高速度

伪代码只需要保留左右边界和扫描方向

left = 0
right = width - 1

while left < right:
    scan_left_to_right()
    right -= 1
    scan_right_to_left()
    left += 1

游戏里的移动比一次比较更耗费时间，所以减少回到行首和列首的次数会更有价值

收获前检查

正式收获前可以按这个顺序检查

  1. 每个位置都已经种上仙人掌
  2. 行排序和列排序使用同一个比较方向
  3. 所有无人机都已经 wait_for()
  4. 排序函数使用了正确的宽度和高度
  5. 调试时确认主无人机没有停在意外位置
  6. 先用小尺寸测试，再扩大到完整世界
